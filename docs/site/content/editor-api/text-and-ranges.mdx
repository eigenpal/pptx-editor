Use `shape.textFrame.textRange` for a shape’s full text. Use `getSubstring(start, length)` to work with a smaller range.

The example accepts a runtime from [Runtime and lifecycle](/docs/editor-api/runtime). The target shape must have a text frame.

## Replace one occurrence

Load the text, find the target, and synchronize the replacement:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function replaceText(
  runtime: PptxEditorRuntime,
  slideId: string,
  shapeId: string,
  search: string,
  replacement: string
) {
  if (!search) throw new Error('Search text must not be empty');
  return runtime.run(async (context) => {
    const slide = context.presentation.slides.getItem(slideId);
    const range = slide.shapes.getItem(shapeId).textFrame.textRange;
    range.load('text');
    await context.sync();
    const start = range.text.indexOf(search);
    if (start === -1) return false;
    range.getSubstring(start, search.length).text = replacement;
    await context.sync();
    return true;
  });
}
```

Offsets use UTF-16 code units, as JavaScript string indexes do. Do not split a surrogate pair. Paragraph breaks read as `\r`; line breaks read as `\v`. If another writer changes the presentation after the read, the write can fail with `StaleDocument`. Read the text again and reconsider the replacement before retrying.

## Replace text across the presentation

Use `Presentation.replaceAll` to replace every match in one call. It returns the number of matches after the sync:

```ts
await runtime.run(async (context) => {
  const count = context.presentation.replaceAll('FY25', 'FY26', { matchWholeWord: true });
  await context.sync();
  console.log(`${count.value} replaced`);
});
```

The search reads the shapes on each slide, also in groups. It also reads the table cells that the slide shows and the speaker notes. It does not read charts, diagrams, layouts, or masters. To replace on one slide, call `replaceAll` on that `Slide`. It reads the shapes, the table cells, and the speaker notes of that slide.

```ts
const slide = context.presentation.slides.getItemAt(0);
const count = slide.replaceAll('{{client}}', 'Northwind', { matchCase: true });
await context.sync();
```

Letters match in either case unless you set `matchCase`. With `matchWholeWord`, no letter, digit, combining mark, or underscore can touch either end of a match.

The new text takes the font of the run that holds the first replaced character. A match that starts at a line break takes the font of the text before it. A match stays in one paragraph. The call refuses search text with `\r` or `\n` with `InvalidArgument`. Search for a line break with `\v`. A field, such as a slide number, or an equation is never part of a match. The call refuses search text with U+FFFC, the character that stands for a field in the search. The replacement is one line: a line break, a paragraph break, or a tab in it becomes a space. An empty replacement deletes each match. Search text and replacement text take at most 1000 characters.

With no match, nothing changes and the count is 0. In a browser runtime, the sync is one undo step. `Presentation.replaceAll` and `Slide.replaceAll` are SDK extensions: the pinned Office.js reference has no such members.

## Format a range

Inside a `run()` callback, set properties on a known text range:

```ts
// range is the TextRange you selected in this run.
range.font.bold = true;
range.font.size = 24;
range.font.color = '#1F4E79';
range.paragraphFormat.horizontalAlignment = 'Center';
await context.sync();
```

A formatting read returns `null` when the range has mixed values. Narrow that value before reusing it in a write. Paragraph formatting applies to the paragraphs that the range touches.

## Highlight text

`font.highlightColor` reads and sets the text highlight. It is an SDK extension, not a member of the pinned Office.js reference.

```ts
// shape is a Shape with a text frame, loaded in this run.
const text = shape.textFrame.textRange;
// Remove every highlight. The other character formatting stays.
text.font.highlightColor = null;
// Highlight the first five characters.
const first = text.getSubstring(0, 5);
first.font.highlightColor = '#FFFF00';
first.font.load('highlightColor');
await context.sync();
console.log(first.font.highlightColor); // '#FFFF00'
```

A read returns `#RRGGBB`. It returns `null` when the text has no highlight and when the range has mixed highlights. A write takes `#RRGGBB` or one of these color names: `black`, `white`, `red`, `green`, `blue`, `yellow`, `orange`, `purple`, `gray`, `grey`, `silver`, `maroon`, `navy`, `teal`, `olive`, `lime`, `aqua`, `fuchsia`, `cyan`, `magenta`, `pink`, `brown`, `gold`, `indigo`, or `violet`. A write of `null` removes the highlight from each run and keeps the other character formatting. A highlight that a list style or a master gives the text still applies. The property also works on `TableCell.font`. `TableCell.textRuns` and the table cell options do not include it.

## Check whether text fits its shape

Use `textFrame.getTextFit()` to find text that overflows its shape, for example before you save a generated slide. Read the result after `context.sync()`:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function writeIfItFits(
  runtime: PptxEditorRuntime,
  shapeId: string,
  text: string,
  shorterText: string
) {
  return runtime.run(async (context) => {
    const frame = context.presentation.slides.getItemAt(0).shapes.getItem(shapeId).textFrame;
    frame.textRange.text = text;
    const fit = frame.getTextFit();
    await context.sync();
    if (!fit.value.overflows) return true;
    frame.textRange.text = shorterText;
    await context.sync();
    return false;
  });
}
```

The result has these fields:

| Field | Value |
| --- | --- |
| `overflows` | `true` when the laid-out text needs more height than the text area has. |
| `textHeight` | The height that the laid-out lines need, in points. |
| `availableHeight` | The height of the text area, in points. The text area is the text rectangle of the shape less the margins before and after the lines. For horizontal text, these are `topMargin` and `bottomMargin`. |
| `substitutedFonts` | The font families that the text names but that the runtime does not have. A metric-compatible substitute is not listed. |

The read uses the same text layout that `shape.getImageAsBase64()` draws. It works on a server runtime with no canvas, because the runtime measures text with its own text engine. A text write in the same sync re-fits the text first, so the read sees the new text. The read does not change the presentation.

The answer depends on `autoSizeSetting`:

- `AutoSizeShapeToFitText`: the shape grows to fit its text, so the text does not overflow after a text write.
- `AutoSizeTextToFitShape`: the text shrinks in steps. `overflows` is `true` only when the smallest step still does not fit. For one exception, see the empty paragraphs rule below.
- `AutoSizeNone`: `overflows` reports the overflow of the text at its size.

The read uses the shrink step and the shape size that the presentation stores. A write of text, font, paragraph format, or text frame properties in this API re-fits them. A change to the shape size, for example `shape.height`, does not re-fit them. A presentation that you open keeps its stored values until such a write.

These rules apply to the layout:

- Empty paragraphs at the end of the text do not count, because they draw nothing below the text. One case differs: text in one column with middle or bottom anchoring. There, they count, because they push the visible text up. The shrink steps do not count them, so such text can overflow at the step that `AutoSizeTextToFitShape` selects.
- An empty text frame reports the height of one empty line.
- Vertical text measures across its lines. For this text, `availableHeight` is along the width of the shape, less the side margins.
- With columns, `textHeight` is the bottom of the lowest line. When the text flows into a second column, `textHeight` is at least `availableHeight`.
- The read checks the height only. With `wordWrap` set to `false`, a line can run past the sides of the shape, and `overflows` stays `false`.
- Text with a warp preset reports its layout before the warp.

### Fonts

The result depends on the fonts that the runtime measures with. A server runtime tries the fonts in this order:

1. The faces in the `fonts` option of `createServer`.
2. The fonts embedded in the presentation.
3. The metric-compatible substitutes. The `substitutes` option loads them, and its default is `true`.

A metric-compatible substitute has the advance widths of the font that it replaces. Thus, the line breaks and the heights do not change. Any other substitute can break lines in other places, and so change `textHeight`. Such substitutes are in `substitutedFonts`. For an exact answer, give the runtime the fonts in that list through the `fonts` option. See [Runtime and lifecycle](/docs/editor-api/runtime).

### Limits

These targets refuse the read with `NotSupported`:

- A shape with no text frame: a picture, a connector, a group, or a table (diagnostic `edit.no-text-frame`). The API has no fit read for a table cell. A table row grows to fit the horizontal text of its cells.
- A shape of a slide layout or a slide master (diagnostic `text-fit.not-on-slide`).
- A hidden shape, or a shape in a hidden group (diagnostic `text-fit.not-drawn`).
- Any shape while the runtime has no exact font measurement (diagnostic `host.no-font-measurement`). A runtime has none when it has no font at all. For example, a server runtime with `substitutes: false`, no `fonts`, and no embedded fonts has none. A runtime over a live editor can also have none while its fonts load, or when its text engine does not load.

A text frame from `getTextFrameOrNullObject()` that is a null object skips the read, and the result stays not loaded. `getTextFit()` is an SDK extension. The pinned Office.js reference has no such member.

## Check text targets

Pictures, connectors, tables, and groups do not expose an editable text frame through this API. A direct text read on those shapes fails with `NotSupported` and diagnostic `edit.no-text-frame`. Use [Tables](/docs/editor-api/tables) for table cell text.
