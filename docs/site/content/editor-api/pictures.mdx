Use `shapes.addPicture()` to place a picture on a slide. Use `getImageAsBase64()` to render a slide or shape as PNG. Check `runtime.capabilities.images` before you render. Browser runtimes use a canvas. Server runtimes require a `rasterize` callback.

## Add a picture shape

This function adds a logo to the first slide and returns its id. It works in the server and browser runtimes:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function addLogo(runtime: PptxEditorRuntime, logoBase64: string) {
  return runtime.run(async (context) => {
    const slide = context.presentation.slides.getItemAt(0);
    const logo = slide.shapes.addPicture(logoBase64, { left: 24, top: 24, width: 120 });
    logo.altTextDescription = 'Company logo';
    logo.load('id');
    await context.sync();
    return logo.id;
  });
}
```

`addPicture` is an SDK extension. Pass the Base64 bytes of a PNG, JPEG, or GIF image of at most 50 MiB. Do not add a `data:` URL prefix. The bytes go into a new image part of the presentation. Other bytes, SVG among them, refuse with `InvalidArgument` at the sync. The refused call writes nothing.

The options give the box in points:

- With no size, the picture keeps its aspect ratio and fits 60% of the slide, centered. It is never larger than its own size. When the image states no resolution, the engine uses 96 pixels per inch.
- With only `width` or only `height`, the other keeps the aspect ratio.
- When you give a size, the engine centers each missing `left` or `top` on the slide.

`Shape.type` reads `Image`. The new shape has no alt text. Set `altTextDescription` in the same batch. The picture never fills an empty placeholder. One sync is one undo step. You can also add a picture to `slideLayout.shapes` or `slideMaster.shapes`.

## Render a slide preview

This function returns PNG data as a base64 string:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function renderPreview(runtime: PptxEditorRuntime) {
  if (!runtime.capabilities.images) {
    throw new Error('This runtime needs an image rasterizer');
  }
  return runtime.run(async (context) => {
    const slide = context.presentation.slides.getItemAt(0);
    const result = slide.getImageAsBase64({ width: 960 });
    await context.sync();
    return result.value;
  });
}
```

Read `ClientResult.value` only after synchronization. To render one shape, call `shape.getImageAsBase64({ width: 320 })`. A shape preview is clipped to its box. A hidden slide (`slide.hidden`) renders as any other slide.

The output preserves the aspect ratio and fits the requested pixel dimensions. Without dimensions, the output uses the source size at 96 pixels per inch. Shape previews accept only the `Png` format.

## Set a picture fill

Inside a run, pass base64 image bytes to the shape fill:

```ts
// shape belongs to this run. imageBase64 contains PNG, JPEG, or GIF bytes.
shape.fill.setImage(imageBase64);
await context.sync();
```

The image stretches to the shape. Table cells refuse picture fills. This operation changes a fill. To add a picture shape, use `addPicture`. The API does not fetch an image URL for you.

## Configure server rendering

Follow [Draw pictures on a server](/docs/editor-api/runtime#draw-pictures-on-a-server) to supply a rasterizer. Its PNG output must have exactly the requested width and height. Use supplied font bytes only for that request and release temporary font registrations afterward.
