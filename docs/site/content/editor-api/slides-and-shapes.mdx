description: 'Find slides, add shapes, and change their positions with the editing API.'

Use `context.presentation.slides` to find slides. Each slide exposes a `shapes` collection. Positions and sizes use points. Collection indexes start at zero.

The examples accept a runtime from [Runtime and lifecycle](/docs/editor-api/runtime). The first example requires a presentation with at least one slide.

## Add a shape

Create and format a shape in one batch:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function addLabel(runtime: PptxEditorRuntime) {
  await runtime.run(async (context) => {
    const shapes = context.presentation.slides.getItemAt(0).shapes;
    const label = shapes.addGeometricShape('Rectangle', {
      left: 40,
      top: 80,
      width: 240,
      height: 60,
    });
    label.name = 'Summary';
    label.fill.setSolidColor('#1F4E79');
    label.textFrame.textRange.text = 'Quarterly results';
    label.textFrame.textRange.font.color = '#FFFFFF';
    await context.sync();
  });
}
```

`addTextBox()` creates a text box. `addGeometricShape()` creates a preset geometry. The returned shape works in the same batch without a preliminary load.

## Add and find a slide

`slides.add()` returns no slide proxy. Synchronize, load the collection, and then find the added slide:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function appendSlide(runtime: PptxEditorRuntime) {
  return runtime.run(async (context) => {
    const slides = context.presentation.slides;
    slides.add();
    await context.sync();
    slides.load('items/id');
    await context.sync();
    return slides.items[slides.items.length - 1]!.id;
  });
}
```

Pass `layoutId` and `slideMasterId` to choose a layout and master explicitly. Use identifiers returned from the same presentation.

## Duplicate a slide

Use `slide.duplicate()` to copy a slide inside the same presentation. It returns the copy. Use the copy in the same batch, with no load first:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function duplicateFirstSlide(runtime: PptxEditorRuntime) {
  return runtime.run(async (context) => {
    const copy = context.presentation.slides.getItemAt(0).duplicate();
    copy.tags.add('VARIANT', 'B');
    copy.load('id,index');
    await context.sync();
    return { id: copy.id, index: copy.index };
  });
}
```

The copy goes directly after the source slide, in the same section, with a new slide id. It keeps the layout, the master, and the pictures of the source. It gets its own notes, charts, diagrams, comments, embedded objects, and tags. A change to one slide does not change the other. A slide with an embedded control is refused with `NotSupported` and diagnostic `edit.slide-has-controls`. In a live editor, the sync that copies the slide is one undo step. This method works with browser and server runtimes. It is an SDK extension, not a member of the pinned Office.js reference.

## Move and remove content

Use `slide.moveTo(index)` to reorder slides. Set a shape’s `left`, `top`, `width`, or `height` to reposition it. Use `shape.delete()` or `slide.delete()`, then synchronize. Deleting the last slide is refused with diagnostic `edit.last-slide`.

A shape identifier belongs to its slide. Keep the slide identifier with stored shape identifiers. A duplicate shape identifier in one slide prevents writes to that shape.

## Hide and show slides

Use `slide.hidden` to read or change whether a slide is hidden. A slide show skips a hidden slide. This example hides the slides at the given positions and returns the identifiers of all hidden slides:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function hideSlides(runtime: PptxEditorRuntime, positions: number[]) {
  return runtime.run(async (context) => {
    const slides = context.presentation.slides;
    for (const position of positions) slides.getItemAt(position).hidden = true;
    await context.sync();
    slides.load('items/id,items/hidden');
    await context.sync();
    return slides.items.filter((slide) => slide.hidden).map((slide) => slide.id);
  });
}
```

The write applies at the next `context.sync()`. A load of `hidden` queued after the write, in the same or a later synchronization, reads the new value. Setting `true` saves `show="0"` on the `p:sld` element, and setting `false` removes the attribute. Setting the current value writes nothing. A value that is not a boolean is refused with `InvalidArgument`. Browser and server runtimes behave the same, and a browser runtime records the change as one undo step.

A hidden slide stays in `presentation.slides`. `slide.getImageAsBase64()` draws a hidden slide. A PDF export from `@pptx-editor.dev/pptx-to-pdf` leaves hidden slides out unless you set `includeHiddenSlides: true`. `slide.hidden` is an SDK extension, not a member of the pinned Office.js reference.

## Read and write speaker notes

Use `slide.speakerNotes` to read or replace the speaker notes of a slide as plain text. This example adds a source line to the notes of one slide and returns the new notes:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function addSource(runtime: PptxEditorRuntime, position: number, source: string) {
  return runtime.run(async (context) => {
    const slide = context.presentation.slides.getItemAt(position).load('speakerNotes');
    await context.sync();
    const lines = slide.speakerNotes ? [slide.speakerNotes] : [];
    slide.speakerNotes = [...lines, `Source: ${source}`].join('\n');
    await context.sync();
    slide.load('speakerNotes');
    await context.sync();
    return slide.speakerNotes;
  });
}
```

A read joins the paragraphs of the notes with `\n`. A line break inside a paragraph also reads as `\n`. A slide with no notes reads as an empty string. `TextRange.text` joins paragraphs with `\r`, but the notes text uses `\n`.

A write makes one paragraph for each line. `\n`, `\r\n`, `\r`, and `\v` each end a line. The write changes only the text that differs, so unchanged text keeps its formatting. A line break that the write does not change stays a line break. New text takes the formatting of the place where it goes. A write of text to a slide with no notes creates the notes slide from the notes master. A write of an empty string to that slide creates nothing.

The write applies at the next `context.sync()`, and a browser runtime records each synchronization as one undo step. Browser and server runtimes behave the same. The API refuses a value that is not a string, longer than 1,000,000 characters, or with a character that XML cannot hold. The refusal has the code `InvalidArgument`, and nothing in that synchronization applies. When the presentation has no notes master, a write that must create a notes slide refuses with `NotSupported`. The diagnostic is `edit.no-notes-master`. A notes slide with no body placeholder refuses a write with `NotSupported` and the diagnostic `edit.no-notes-placeholder`. `Presentation.replaceAll` and `Slide.replaceAll` also search the speaker notes. `slide.speakerNotes` is an SDK extension, not a member of the pinned Office.js reference.

## Set slide transitions

Use `slide.transition` to read or change the transition of a slide. The transition is the effect that shows the slide, its duration, and its advance settings. Call `transition.set()` to write several settings in one step. To apply one transition to every slide, load the slides and loop over them in one synchronization:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function fadeEverySlide(runtime: PptxEditorRuntime) {
  return runtime.run(async (context) => {
    const slides = context.presentation.slides.load('items');
    await context.sync();
    for (const slide of slides.items) {
      slide.transition.set({ effect: 'Fade', durationMs: 700, advanceAfterMs: null });
    }
    await context.sync();
    slides.load('items/transition/effect');
    await context.sync();
    return slides.items.map((slide) => slide.transition.effect);
  });
}
```

The writes of one `context.sync()` are one transaction. A browser runtime records them as one undo step. Browser and server runtimes behave the same. To remove the transition of a slide, call `slide.transition.remove()`.

`SlideTransition` has these properties:

| Property | Values | Saved as |
| --- | --- | --- |
| `effect` | `None`, `Fade`, `Push`, `Wipe`, `Split`, or `Cut`. Other standard effects, such as `Dissolve`, and `Other` are read only. | The effect element of `p:transition` |
| `durationMs` | 10 to 59,000 milliseconds | `p14:dur`, and the nearest speed `spd` |
| `advanceOnClick` | `true` or `false` | `advClick` |
| `advanceAfterMs` | 0 to 3,600,000 milliseconds, or `null` for no automatic advance | `advTm` |
| `direction` | `Left`, `Up`, `Right`, or `Down` for `Push` and `Wipe`. `HorizontalIn`, `HorizontalOut`, `VerticalIn`, or `VerticalOut` for `Split`. `null` for other effects. | `dir`, and `orient` for `Split` |
| `throughBlack` | `true` or `false`, for `Fade` and `Cut` | `thruBlk` |

A slide with no transition reads `None`, 750 ms, advance on click, and no advance time. A standard effect reads by its element name. An effect from an extension namespace reads `Other`. A write of the timing or the direction keeps the effect and the `mc:AlternateContent` branches that hold it. A write of a new effect replaces the transition markup. It keeps the duration, the advance settings, the transition sound (`p:sndAc`), and the extensions. A new `Push` goes up, and a new `Split` is `VerticalOut`, unless the same `set()` call sets `direction`.

On a slide with an effect, `effect: 'None'` removes the effect, the sound, and the extensions. It keeps the advance settings. `remove()` removes the whole `p:transition`, also on a slide that holds only a sound. A write that does not set `effect` never removes markup. After `None`, set the effect and the duration in one `set()` call. A slide with no `p:transition` reads 750 ms. A slide that keeps an empty `p:transition` reads its speed, 500 ms by default.

These writes refuse with `NotSupported`, and nothing in that synchronization is written:

- A duration on a slide with no effect (`edit.transition-no-effect`). Set the effect and the duration in the same `set()` call.
- A `direction` or `throughBlack` value for an effect that does not take it (`edit.transition-option-not-supported`).
- A duration other than 500, 750, or 1000 ms on an extension effect that has no duration branch (`edit.transition-speed-only`).

A read-only effect, an unknown name, or a value out of range refuses with `InvalidArgument`, and nothing is written. Setting the current value writes nothing.

`slide.transition`, `SlideTransition`, `SlideTransitionEffect`, and `SlideTransitionDirection` are SDK extensions, not members of the pinned Office.js reference. Layouts and masters do not have this property.

## Edit line width, dashes, and endpoints

Use `shape.lineFormat` to read or change line properties in either runtime. This example formats the first shape, which must be a supported line or connector:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function formatConnector(runtime: PptxEditorRuntime) {
  return runtime.run(async (context) => {
    const line = context.presentation.slides.getItemAt(0).shapes.getItemAt(0).lineFormat;
    line.load(['weight', 'beginArrowheadStyle', 'endArrowheadStyle']);
    await context.sync();
    const previousWidth = line.weight;

    line.weight = 2.25;
    line.dashStyle = 'DashDot';
    line.beginArrowheadStyle = 'Diamond';
    line.endArrowheadStyle = 'Triangle';
    await context.sync();
    return previousWidth;
  });
}
```

The first synchronization loads the values used by the example. The second batches independent property writes. Omit the first read when you do not need previous values. Keep line proxies inside `runtime.run()`. Handle rejected synchronizations with the runtime's [error handling](/docs/editor-api/runtime).

`weight` uses points. `beginArrowheadStyle` and `endArrowheadStyle` accept `None`, `Triangle`, `Open`, `Stealth`, `Oval`, or `Diamond`. These endpoint properties extend the editing API. Changing an endpoint type preserves its imported dimensions and extension content. Setting one endpoint leaves the other unchanged. Use `None` to hide a marker. `Open` maps to the DrawingML `arrow` value. These properties are SDK extensions, not members of the pinned Office.js reference.

## Edit gradient and effect properties

Use `shape.getFormat()` to read detailed solid fill, gradient, shadow, and reflection values. Read its result after `context.sync()`. Use `shape.patchFormat()` to change specified properties while preserving unrelated XML. These methods extend the editing API and work with browser and server runtimes.

This example changes the middle stop of an existing gradient on the first shape:

```ts
import type { PptxEditorRuntime } from '@pptx-editor.dev/editor-api';

export async function adjustGradient(runtime: PptxEditorRuntime) {
  return runtime.run(async (context) => {
    const shape = context.presentation.slides.getItemAt(0).shapes.getItemAt(0);
    const result = shape.getFormat();
    await context.sync();

    const gradient = result.value.gradient;
    const stop = gradient?.stops[1];
    if (!gradient || gradient.kind !== 'linear' || !stop) return false;

    shape.patchFormat({
      kind: 'gradient',
      angle: 45,
      stop: { id: stop.id, opacity: 0.6 },
    });
    await context.sync();
    return true;
  });
}
```

The first synchronization reads the stop identity needed by the write. The second applies the patch. Batch independent shape patches before the same synchronization. A missing shape or unsupported edit rejects the synchronization; use the runtime's [error handling](/docs/editor-api/runtime).

Patch lengths use points, angles use degrees, and positions and opacity use fractions from zero to one. A stop color accepts an RGB string or a supported theme color choice. Angles accept zero to 360 degrees; 360 writes zero. Shadow and reflection blur and distance accept zero to 150 points. Omitted properties retain their source XML. Changing opacity preserves the source color and its unrelated transforms. Changing a color intentionally replaces that color representation.

The read result's `solid` holds the color and opacity of a solid fill, and is `null` for other fills. A solid patch, `{ kind: 'solid', opacity }`, sets the fill transparency and keeps the source color. Shadow patches accept `blur`, `distance`, `angle`, `opacity`, `color`, and `rotWithShape` where applicable. Reflection patches accept `blur`, `distance`, `startOpacity`, `endOpacity`, `startPosition`, `endPosition`, and `rotWithShape`. These patches edit existing effects; they do not create effects or flatten unsupported effect graphs. Gradient patches also accept `addStop` and `removeStop`. A new stop requires `position` and `color`; its optional `opacity` defaults to one. `removeStop` takes a stop identity and retains at least two stops. Adding a stop allows at most ten stops. Imported gradients with more stops remain inspectable and editable.

Stop identities belong to a read result; they are not durable identifiers. Read them again after structural edits or after an inherited fill becomes an object override. Patches within the same synchronization retain the mapping to copied inherited stops.

An unsupported effect graph sets `effectsReason` in the read result. Its shadow and reflection details remain unavailable, but an independent supported gradient remains readable and editable. Effect patches still refuse unsupported graphs and preserve their content.
