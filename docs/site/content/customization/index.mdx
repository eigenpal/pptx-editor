Customize your PPTX editor to fit your application. Each guide lists the supported options and shows React and Vue reference code. The API has the same shape as DOCX Editor's, so one host can customize both products the same way.

## Live examples

The demo app in [`examples/vite/`](https://github.com/eigenpal/pptx-editor/tree/main/examples/vite) composes these parts into a complete editor. In a checkout of the repository, run `bun install` and `bun run dev`, then open `http://localhost:5274/`.

## Design principles

The PPTX editor separates presentation editing from interface controls. Every part reads the same editor state and runs the same commands as the packaged editor.

Start with the smallest change that fits your application:

- **Appearance:** Set `--doc-*` CSS properties on `.acme-theme .pptx-editor`, where `.acme-theme` is a wrapper around `PptxEditor.Root`. Use `className` and `data-active` or `data-disabled` to style controls. Set `colorMode` for dark controls.
- **Composition:** Use `PptxEditor.Root`, `.Viewport`, `.Content`, and the panes to arrange the interface. Keep every part inside `Root`.
- **Individual controls:** Use named parts such as `PptxEditor.Toolbar.Bold`. Replace an icon with `icon`, or supply your own element with `asChild`.
- **Control sets:** Override a slot in place, use `hidden` to remove it, or set `preset={false}` to compose the toolbar, a menu, or a dialog yourself.
- **Custom behavior:** Use `useEditorCommand(slotId)` for command state and execution. Use `useEditorState(selector)` for the state your control shows.

Keep the slide selection when you build custom controls: a chrome `mousedown` calls `preventDefault()`, except on inputs, selects, and text areas. Keep labels, keyboard support, and disabled reasons accessible. A disabled control stays focusable with `aria-disabled` and tells the user why it is disabled.

Hiding a control changes the interface only. The operation keeps working from menus, keyboard shortcuts, and the API.

## Choose the API level

| Level | Use |
| --- | --- |
| Props and CSS tokens | Change labels, colors, and color mode. |
| Named parts | Arrange controls and replace selected elements. |
| Hooks and composables | Connect application controls to editor state and commands. |
| Modules | Add review, collaboration, or drawing effects (glow, inner shadow, reflection, soft edge) with [`@pptx-editor.dev/pro`](https://www.npmjs.com/package/@pptx-editor.dev/pro) (EigenPal Pro License). Pass them in the `modules` prop of `PptxEditor` or its root, as in DOCX Editor; the editor reads it once, when it is created. See [Capability modules](/docs/react/props#capability-modules) for an example. |

## React and Vue reference

<FrameworkTabs variant="block">
<Framework value="react">

```tsx
import { PptxEditor } from '@pptx-editor.dev/react';
import '@pptx-editor.dev/core/styles/editor.css';

export function DeckEditor({ bytes }: { bytes: Uint8Array }) {
  return (
    <div className="acme-theme">
      <PptxEditor.Root document={bytes} colorMode="system">
        <PptxEditor.Viewport className="deck-workspace">
          <PptxEditor.Menu />
          <div className="deck-workspace__dock">
            <PptxEditor.Toolbar />
          </div>
          <div className="deck-workspace__body">
            <PptxEditor.SlideRail />
            <div className="deck-workspace__main">
              <PptxEditor.Content />
              <PptxEditor.FindBar />
              <PptxEditor.EditNotice />
              <PptxEditor.FontNotice />
              <PptxEditor.NotesPane />
              <PptxEditor.ZoomPill />
            </div>
          </div>
          <PptxEditor.Slideshow />
        </PptxEditor.Viewport>
      </PptxEditor.Root>
    </div>
  );
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import {
  PptxEditorContent,
  PptxEditorRoot,
  PptxEditorToolbar,
  PptxEditorViewport,
} from '@pptx-editor.dev/vue';
import '@pptx-editor.dev/core/styles/editor.css';

defineProps<{ bytes: Uint8Array }>();
</script>

<template>
  <div class="acme-theme">
    <PptxEditorRoot :document="bytes" color-mode="system">
      <PptxEditorViewport class="deck-workspace">
        <div class="deck-workspace__dock">
          <PptxEditorToolbar />
        </div>
        <div class="deck-workspace__body">
          <div class="deck-workspace__main">
            <PptxEditorContent />
          </div>
        </div>
      </PptxEditorViewport>
    </PptxEditorRoot>
  </div>
</template>
```

</Framework>
</FrameworkTabs>

The `deck-workspace` classes are your own layout CSS. [Workspace layout](/docs/customization/layout#workspace-layout) lists it.

The Vue adapter has the menu bar (`PptxEditorMenu`) and the context menus (`PptxEditorContextMenu`, `RailContextMenu`, `SectionContextMenu`). It has the panes: the slide rail (`PptxEditorSlideRail`), the slide sorter (`PptxEditorSlideSorter`), the notes pane (`PptxEditorNotesPane`), the side panel (`PptxEditorSidePanel`), and the zoom pill (`PptxEditorZoomPill`). It has the find bar (`PptxEditorFindBar`), the slide show (`PptxEditorSlideshow`), the font and edit notices (`PptxEditorFontNotice`, `PptxEditorEditNotice`), and the link popup, which `PptxEditorRoot` hosts. Its toolbar and ribbon draw the same controls as React's; see [Toolbar](/docs/customization/reference/toolbar#react-and-vue-reference). The parity contract (`scripts/parity/parity.contract.json`) maps each React prop and export to its Vue twin.
