Compose the editor from parts inside `PptxEditor.Root`. `Root` owns the editor and renders no element. For every part and prop, see the [layout reference](/docs/customization/reference/layout).

## Workspace layout

The packaged `PptxEditor` uses this arrangement, and a composed editor works best with the same one. The toolbar is on top. Under it, a row holds the slide rail, a main column, and an optional side panel. The main column holds the canvas, the floating parts, and the notes pane. In the packaged editor, the view switch, the zoom pill, and the font notice float above the notes pane at every notes height. The canvas leaves room for them under the fitted slide.

<FrameworkTabs>
<Framework value="react">

```tsx
import { useState } from 'react';
import { PptxEditor } from '@pptx-editor.dev/react';
import '@pptx-editor.dev/core/styles/editor.css';

export function Workspace({ bytes }: { bytes: Uint8Array }) {
  const [panel, setPanel] = useState(false);
  return (
    <div className="acme-theme">
      <PptxEditor.Root document={bytes}>
        <PptxEditor.Viewport className="deck-workspace">
          <div className="deck-workspace__dock">
            <PptxEditor.Toolbar />
            <button type="button" aria-pressed={panel} onClick={() => setPanel(!panel)}>
              Format
            </button>
          </div>
          <div className="deck-workspace__body">
            <PptxEditor.SlideRail paneWidth={220} />
            <div className="deck-workspace__main">
              <PptxEditor.Content />
              <PptxEditor.FindBar />
              <PptxEditor.EditNotice />
              <PptxEditor.FontNotice />
              <PptxEditor.Loading overlay />
              <PptxEditor.NotesPane defaultOpen={false} style={{ maxHeight: 240 }} />
              <PptxEditor.ZoomPill />
            </div>
            {panel && <PptxEditor.SidePanel paneWidth={320} onClose={() => setPanel(false)} />}
          </div>
          <PptxEditor.Slideshow />
        </PptxEditor.Viewport>
      </PptxEditor.Root>
    </div>
  );
}
```

The `deck-workspace` classes are your own CSS:

```css
.acme-theme {
  height: 100vh;
}
.deck-workspace {
  display: flex;
  flex-direction: column;
  height: 100%;
  min-height: 0;
  background: var(--doc-bg);
}
.deck-workspace__dock {
  display: flex;
  justify-content: center;
  padding: 8px 14px 10px;
}
.deck-workspace__body {
  display: flex;
  flex: 1 1 auto;
  min-height: 0;
  padding-left: 12px;
}
.deck-workspace__main {
  position: relative;
  display: flex;
  flex-direction: column;
  flex: 1 1 auto;
  min-width: 0;
  min-height: 0;
}
```

| Part | Requirement |
| --- | --- |
| `PptxEditor.Viewport` | The styling scope: a plain block element with no layout of its own. Give it a height, or a flexible parent with `min-height: 0`. It is a landmark region named **Presentation editor**, so a screen reader user can go to the editor. |
| Each flex level | Keep `min-height: 0`, so the canvas and the rail scroll inside the window instead of growing the page. |
| The main column | `position: relative`. The zoom pill, the find bar, and the notices use absolute positions. |
| `PptxEditor.Toolbar`, `PptxEditor.Menu` | Inside `PptxEditor.Viewport`. Their menus render inside the viewport and take its tokens. |
| `PptxEditor.Content` | Attaches the slide canvas. |

`Root` hosts the link popup. Ctrl+K (Cmd+K on macOS), the toolbar's link control, and **Insert > Link…** work with no toolbar on the page. Keep every part, menu, and application control that uses the editor under the same root.

### Name the editor landmark

The viewport is a `region` landmark with the name **Presentation editor** (`viewport.ariaLabel`). The slide rail (`navigation`, **Slides**) and the speaker notes (`region`, **Speaker notes**) are landmarks inside it. When a page shows more than one editor, give each one its own name with `label`. It takes text or a translation key.

When your own landmarks (`header`, `main`, `aside`) are inside the viewport, set `label={false}`. The viewport then renders no region, and your landmarks stay at the top level. Put the toolbar and the canvas in your `main`.

```tsx
<PptxEditor.Viewport label={false}>
  <header>{/* your app bar */}</header>
  <main>
    <PptxEditor.Toolbar />
    <PptxEditor.Content />
  </main>
</PptxEditor.Viewport>
```

In Vue, write `<PptxEditorViewport :label="false">`.

## Change one part of the packaged editor

The packaged `<PptxEditor>` takes DOCX Editor's part props. Each prop takes `true`, `false`, or the props object of its part. An object adds the part with those props, so you can change one part and keep the packaged editor.

```tsx
<PptxEditor
  document={bytes}
  menu={{ children: <PptxEditor.Menu.Arrange hidden /> }}
  contextMenu={{ children: <PptxEditor.ContextMenu.Cut hidden /> }}
  slideRail={{ orientation: 'horizontal' }}
  notesPane={false}
/>
```

| Prop | Part | Default |
| --- | --- | --- |
| `toolbar` | `PptxEditor.Toolbar` (`ToolbarProps`). | `true` |
| `menu` | `PptxEditor.Menu` (`MenuProps`), above the toolbar. | `false` |
| `contextMenu` | `PptxEditor.ContextMenu` (`PptxEditorContextMenuProps`). It sets `popups.contextMenu`, and a `popups.contextMenu` entry wins over it. | `true` |
| `hyperlinkPopup` | The packaged link popup. `false` acts as `popups.hyperlink: false`. | `true` |
| `slideRail` | `PptxEditor.SlideRail` (`SlideRailProps`), as DOCX Editor's `navigation`. | `true` |
| `notesPane` | `PptxEditor.NotesPane` (`NotesPaneProps`). | `true` |
| `openFailure` | `PptxEditor.OpenFailure` (`PptxEditorOpenFailureProps`). See [Open failure](#open-failure). | `true` |

In Vue, pass the same props to `PptxEditor`, for example `:menu="true"` and `:notes-pane="false"`. DOCX Editor has no status bar prop, so the packaged editor has none either. To show `PptxEditor.StatusBar`, compose the editor.

## Switch between Normal and Slide Sorter

The packaged `PptxEditor` swaps its workspace when the view changes. In a composed editor, read the view with `useEditorState` and make the same switch. The `view.presentationView` slot, in the View menu or a toolbar, changes the view.

```tsx
import { PptxEditor, useEditorState } from '@pptx-editor.dev/react';

export function Workspace() {
  const sorter = useEditorState((s) => s.presentationView === 'slideSorter');
  return sorter ? (
    <PptxEditor.SlideSorter />
  ) : (
    <>
      <PptxEditor.SlideRail />
      <PptxEditor.Content />
      <PptxEditor.NotesPane />
    </>
  );
}
```

## Slide rail parts

The action row under the thumbnails has named parts, as `PptxEditor.Toolbar` and `PptxEditor.StatusBar` have. A named child replaces its part in place. Other children go after **Delete**. `preset={false}` renders only your children, in your order.

```tsx
<PptxEditor.SlideRail orientation="horizontal">
  <PptxEditor.SlideRail.MoveEarlier hidden />
  <PptxEditor.SlideRail.MoveLater hidden />
  <PptxEditor.SlideRail.AddSlide icon={<PlusIcon />} className="acme-add" />
  <PptxEditor.SlideRail.Action label="Ask for feedback" icon={<ChatIcon />} onSelect={ask} />
</PptxEditor.SlideRail>
```

A horizontal rail narrower than 420 pixels, as on a phone, keeps **New slide**, **Hide thumbnails**, and your actions in the row. It folds the layout gallery, **Duplicate slide**, the two moves, and **Delete slide** into one **More slide actions** menu. A hidden part stays out of that menu. A vertical rail never folds. In a right-to-left horizontal rail, the earlier move goes to the right: the buttons, the slide menu rows, their shortcuts, and the icons follow the arrow keys.

| Part | Button |
| --- | --- |
| `SlideRail.AddSlide` | **New slide** |
| `SlideRail.ChooseLayout` | The layout gallery |
| `SlideRail.Duplicate` | **Duplicate slide** |
| `SlideRail.MoveEarlier`, `SlideRail.MoveLater` | The two move buttons |
| `SlideRail.Delete` | **Delete slide** |
| `SlideRail.Collapse` | **Hide thumbnails**. `toggle={false}` on the rail removes it. |
| `SlideRail.Expand` | **Show thumbnails**, the one button of the folded strip. `toggle={false}` on the rail removes it. |
| `SlideRail.Action` | Your own button: the same component as `Toolbar.Action`. |

Each slide in the rail and in the slide sorter has the name **Slide 3**, or **Slide 3 (hidden)** for a hidden slide. The name comes from hidden text in the item, not from `aria-label`. The thumbnail art is hidden from assistive technology, so the slide's text is not read as the name of the item. A layout tile has the name of its layout.

Each named part takes `hidden`, `icon`, `className`, and `asChild`. A hidden button keeps its command on the keyboard and in the slide menu. A hidden `SlideRail.Expand` leaves the folded strip with no button. The open rail keeps the current slide in view, also when its panel changes size. For the Vue names, see [React and Vue reference](/docs/customization/reference/layout#react-and-vue-reference).

## Horizontal slide rail

In a tall, narrow host, such as a panel beside a chat, put the rail under the slide as a row. In Vue, pass the same prop to `PptxEditorSlideRail`.

```tsx
<PptxEditor.Content />
<PptxEditor.SlideRail orientation="horizontal" />
<PptxEditor.NotesPane />
```

The row works as the column does. Left and Right step through the slides, and Ctrl+Left and Ctrl+Right (Cmd on macOS) move them. A drag reorders along the row. On a section header, Down expands and Up collapses. **Hide thumbnails** folds the row down. To change the thumbnail width, see [Horizontal rail hooks](/docs/customization/reference/layout#horizontal-rail-hooks).

## Open the slide rail from your chrome

Set `toggle={false}` to remove the rail's own buttons, and control `open` from your application. The example uses the CSS from [Workspace layout](#workspace-layout).

```tsx
export function RailFromHostChrome({ bytes }: { bytes: Uint8Array }) {
  const [rail, setRail] = useState(true);
  return (
    <PptxEditor.Root document={bytes}>
      <PptxEditor.Viewport className="deck-workspace">
        <div className="deck-workspace__dock">
          <button type="button" aria-pressed={rail} onClick={() => setRail(!rail)}>
            Slides
          </button>
          <PptxEditor.Toolbar />
        </div>
        <div className="deck-workspace__body">
          <PptxEditor.SlideRail open={rail} onOpenChange={setRail} toggle={false} />
          <div className="deck-workspace__main">
            <PptxEditor.Content />
          </div>
        </div>
      </PptxEditor.Viewport>
    </PptxEditor.Root>
  );
}
```

## Build a notes toggle

`useNotesPane()` returns `open`, and `setOpen` and `toggle` functions that keep their identity across renders. Without `open`, the notes pane reads the same state.

```tsx
function NotesToggle() {
  const notes = useNotesPane();
  return (
    <button type="button" aria-pressed={notes.open} onClick={notes.toggle}>
      Notes
    </button>
  );
}
```

Render one notes pane in each root. For the pane props and the notes height, see [Pane configuration](/docs/customization/reference/layout#pane-configuration).

## Open failure

The editor refuses a file that it cannot open safely, such as a damaged archive or a file that holds no presentation. When a deck was open before, it stays open. The open-failure notice shows a generic message, says whether the open deck stays, and shows a stable error code. It names no contact of its own.

`<PptxEditor>` renders the notice. A composed editor does not: add `PptxEditor.OpenFailure` (Vue: `PptxEditorOpenFailure`) inside `PptxEditor.Root`, in a positioned box. For its options and the error codes, see [Open-failure options](/docs/customization/reference/layout#open-failure-options).

### Add your own actions

Pass `renderOpenFailureActions` in React, or fill the `#openFailureActions` slot in Vue, to add buttons before **Close**. Each receives the context: `failure`, `message`, and `dismiss()`.

<FrameworkTabs>
<Framework value="react">

```tsx
<PptxEditor
  document={bytes}
  renderOpenFailureActions={({ failure }) => (
    <a className="pptx-open-failure__action" href={`/support?code=${failure.code}`}>
      Get help
    </a>
  )}
/>
```

</Framework>
<Framework value="vue">

```vue
<PptxEditor :document="bytes">
  <template #openFailureActions="{ failure }">
    <a class="pptx-open-failure__action" :href="`/support?code=${failure.code}`">Get help</a>
  </template>
</PptxEditor>
```

</Framework>
</FrameworkTabs>

Send the `code` to your support page, not the file. `renderOpenFailureActions` replaces `openFailure.actions`, so pass only one. With `openFailure={false}` (Vue: `:open-failure="false"`), it renders nothing. Both cases print a development warning.

### Show a banner or a toast

Turn off the notice with `openFailure={false}` (Vue: `:open-failure="false"`), then read the failure with `useOpenFailure` inside the root:

<FrameworkTabs>
<Framework value="react">

```tsx
import { PptxEditor, useOpenFailure } from '@pptx-editor.dev/react';

function OpenFailureBanner() {
  const { failure, message, dismiss } = useOpenFailure();
  if (!failure) return null;
  return (
    <div role="alert" className="banner">
      {message} ({failure.code})
      <button type="button" onClick={() => dismiss(failure)}>
        Dismiss
      </button>
    </div>
  );
}

<PptxEditor document={bytes} openFailure={false}>
  <OpenFailureBanner />
</PptxEditor>;
```

</Framework>
<Framework value="vue">

```vue
<!-- OpenFailureBanner.vue -->
<script setup lang="ts">
import { useOpenFailure } from '@pptx-editor.dev/vue';

const { failure, message, dismiss } = useOpenFailure();
</script>

<template>
  <div v-if="failure" role="alert" class="banner">
    {{ message }} ({{ failure.code }})
    <button type="button" @click="dismiss(failure)">Dismiss</button>
  </div>
</template>
```

Mount the banner in the default slot of `<PptxEditor :document="bytes" :open-failure="false">`.

</Framework>
</FrameworkTabs>

`dismiss` hides only the current refusal. Pass the failure that your UI showed, so a late close cannot hide a newer refusal. `kept` says whether the deck that was open stays open.

## Limits

- Keep the classes that `Viewport` supplies. The tokens and the menus find their scope through `.pptx-editor`.
- Render one notes pane in each root. A second one keeps its own state and prints a development warning.
- In the Slide Sorter view, mount `PptxEditor.SlideSorter`. Without it, a development warning says so.
- Mount `PptxEditor.Slideshow` once inside the viewport, and `PptxEditor.FindBar` for Find and Replace.
