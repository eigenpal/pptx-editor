Core provides the PPTX engine and browser editor. React and Vue add interface components around the same editor contract.

## Install

Install the package directly when your application imports its APIs:

```bash
npm install @pptx-editor.dev/core
```

Keep one resolved copy of core in your application. The adapters use it as a peer dependency.

## Create an editor

This browser helper mounts an editor into an existing element. It returns the instance for your controls and cleanup:

```ts
import { createPptxEditor } from '@pptx-editor.dev/core/editor';
import '@pptx-editor.dev/core/styles/editor.css';

export async function mountPresentation(container: HTMLElement, bytes: Uint8Array) {
  const editor = createPptxEditor({ zoom: 'fit' });
  container.classList.add('pptx-editor');
  try {
    editor.attach(container);
    const result = await editor.load(bytes);
    if (!result.ok) throw new Error(result.reason);
    return editor;
  } catch (error) {
    editor.destroy();
    throw error;
  }
}
```

Give the container a height and available width. Call `editor.destroy()` when your application removes this editor permanently.

The core editor does not add a toolbar, slide rail, or menus. Use the adapters for those components.

## Choose an import

Use the editor entry point for browser integration. Other entry points expose the engine layers:

| Entry point                               | Use                                                  |
| ----------------------------------------- | ---------------------------------------------------- |
| `@pptx-editor.dev/core`                   | Editor exports.                                      |
| `@pptx-editor.dev/core/editor`            | Editor creation, commands, fonts, and image exports. |
| `@pptx-editor.dev/core/contracts`         | Shared editor, snapshot, and command types.          |
| `@pptx-editor.dev/core/store`             | Package read/write and document transactions.        |
| `@pptx-editor.dev/core/cascade`           | Slide inheritance and theme resolution.              |
| `@pptx-editor.dev/core/layout`            | Geometry and text layout without the DOM.            |
| `@pptx-editor.dev/core/output`            | SVG paint from layout records.                       |
| `@pptx-editor.dev/core/automation`        | Automation hosts.                                    |
| `@pptx-editor.dev/core/styles/editor.css` | Editor styles.                                       |

For server-side document editing, start with the [Editing API](/docs/editor-api).

## Read state and run commands

Use `snapshot()` for state and `exec()` for edits. This helper adds a slide when the command is available:

```ts
import type { Editor } from '@pptx-editor.dev/core/contracts';

export function addSlide(editor: Editor) {
  const command = { type: 'addSlide' } as const;
  const allowed = editor.can(command);
  if (!allowed.ok) return allowed;
  return editor.exec(command);
}
```

Check the final result even after `can()`. Commands can be refused when their target is unavailable. For a large target, `can()` makes a shorter check. On a selection of more than 250 shapes, the commands that arrange shapes (`order`, `alignObjects`, `distributeObjects`, `flipObjects`, `duplicate`, `delete`, `group`, and `ungroup`) get a check of the editing mode only, and their argument is not checked. Other commands are checked on the first 250 shapes, and a refusal there gets the full check. A command that passes on the first 250 shapes can still be refused by `exec()`. The `duplicate` command also counts a selection of more than 20,000 XML nodes as large, and the `applyLayout` and `resetSlides` commands a named slide of more than 20,000 XML nodes. The `addSlide` and `addSection` commands always get the full check. While you type, the formatting answers of the text box hold until 300 ms after the last key. `exec()` makes the full check and returns the refusal reason.

| Member                         | Purpose                                                 |
| ------------------------------ | ------------------------------------------------------- |
| `snapshot()`                   | Read the presentation and local view state.             |
| `subscribe(listener)`          | Observe state changes; returns an unsubscribe function. |
| `can(command)`                 | Check whether a command can run.                        |
| `exec(command)`                | Run a command and inspect its result.                   |
| `load(bytes, options?)`        | Open a presentation asynchronously.                     |
| `save()`                       | Return PPTX bytes synchronously, or `null`.             |
| `attach(element)` / `detach()` | Mount or remove the surface.                            |
| `destroy()`                    | Release the editor and its resources.                   |

## Choose an event

Use `onEditorEvent(editor, name, handler)` to observe a specific change. It returns an unsubscribe function.

| Event             | Payload and trigger                                                        |
| ----------------- | -------------------------------------------------------------------------- |
| `change`          | Snapshot after an edit, completed or failed load, or read-only transition. |
| `selectionChange` | Snapshot after selection, current slide, or pending slide count changes.   |
| `rejection`       | Refused edit and its snapshot.                                             |
| `openFailure`     | Refused file and its snapshot.                                             |

Use `subscribe()` when you also need zoom or other view changes. Dispose every subscription when its consumer unmounts.

## Patch selected formatting

Use `shapeFormat()` to inspect one selected shape, picture, or connector in a browser editor. Pass a node identifier to inspect that object on the active part. The returned target captures the document, part, and object identities.

This helper changes an existing shadow's distance without replacing its other properties:

```ts
import type { PptxEditorInstance } from '@pptx-editor.dev/core/editor';

export function setShadowDistance(editor: PptxEditorInstance, points: number) {
  const read = editor.shapeFormat();
  if (!read.ok) return read;
  if (!read.format.shadow) {
    return { ok: false as const, reason: 'The object has no editable shadow.' };
  }
  return editor.exec({
    type: 'patchShapeFormat',
    target: read.format.target,
    patch: { kind: 'shadow', distance: points },
  });
}
```

Check the command result before reporting success. A replaced document or removed target can invalidate the captured target. Lengths use points, angles use degrees, and opacity uses fractions from zero to one. Omitted properties stay unchanged, including source XML that the inspector does not expose. Existing preset commands remain available for intentional style replacement.

`read.format.solid` holds the color and opacity of a solid fill, own or inherited, and is `null` for any other fill. Patch it with `{ kind: 'solid', opacity }` to change the fill transparency. The patch keeps the color and its other transforms. An inherited fill is copied to the shape first.

If the read includes `effectsReason`, its effect details are unavailable. A supported gradient remains readable and editable independently. Effect patches refuse unsupported effect graphs without changing their content.

For batched browser or server editing, use [shape formatting automation](/docs/editor-api/slides-and-shapes#edit-gradient-and-effect-properties).

## Format selected lines

Use the line commands to format selected lines or compatible shape outlines. This helper sets an exact width in points:

```ts
import type { PptxEditorInstance } from '@pptx-editor.dev/core/editor';

export function setSelectedLineWidth(editor: PptxEditorInstance, points: number) {
  return editor.exec({ type: 'setLineWidth', points });
}
```

Check the returned `ok` value and display the refusal reason when the command fails. Widths must exceed zero and must not exceed 1584 points. Setting a width on an invisible outline also gives it the theme text color. Use `setLineColor` with `color: null` to remove the visible outline.

Use `setLineDash` with a `LineDash` value to change its dash pattern. Use `setLineEnds` with `head`, `tail`, or both to change endpoint types. The inspector labels `head` as **Start** and `tail` as **End**. Use `none` to remove an endpoint marker. An omitted endpoint stays unchanged. Endpoint type edits retain imported endpoint dimensions and extension content. An endpoint command refuses a selection containing incompatible objects without partially editing its lines. Each change applies to the compatible selection in one undo step.

Use `formatLineState(editor)` from `@pptx-editor.dev/core/editor` to read shared line values across the selection. It returns exact point widths, endpoint types, and separate mixed-value flags. Check `endsSupported` before offering endpoint controls. A null width or endpoint can mean mixed or unavailable. Do not replace it with a default value.
