Use this page to check which presentation features you can edit, display, and preserve when you save. The feature matrix gives the status of each feature. The lists after it name each place where the renderer, an edit, or the PDF export approximates the ECMA-376 behavior.

## Feature matrix

The matrix reports editing, rendering, and round-trip support separately. A feature can display without editing controls, or survive save without displaying.

| Axis | Question |
| --- | --- |
| Editing | Can a user, or code that drives the editor, change the feature? |
| Rendering | Does the slide display as the ECMA-376 specification and the deck's settings define? |
| Round trip | Does the feature survive open, edit, save, and reopen? |

| Status      | Meaning                                                      |
| ----------- | ------------------------------------------------------------ |
| Full        | Supports the feature.                                        |
| Partial     | Works, with limits.                                          |
| Render only | Displays, but is not editable.                               |
| Preserved   | Stays in the file as inert content through editing and save. |
| Planned     | Not supported yet. Work on it is planned.                    |
| No          | Is not supported.                                            |

The slide show and the image and PDF exports show No for round trip. They write nothing to the `.pptx`, so a save has nothing of theirs to keep.

When a feature needs [`@pptx-editor.dev/pro`](https://www.npmjs.com/package/@pptx-editor.dev/pro) or [`@pptx-editor.dev/pptx-to-pdf`](https://www.npmjs.com/package/@pptx-editor.dev/pptx-to-pdf), its note says so. These packages are under the EigenPal Pro License.

## Round-trip contract

- The editor keeps every part of the package that it does not edit. Unknown elements stay in place as generic nodes, so content the editor does not understand never blocks editing and survives save.
- XML parts are written again in a normalized form. Binary parts, such as pictures, media, and embedded fonts, keep their exact bytes.
- Every edit goes through one document store. An edit that the editor cannot make is refused with a reason. It is never dropped without notice.
- A full round trip means that the feature's own edit is still in the file after save and reopen, that the edit changes no other part, and that the saved copy opens with no repair prompt.
- A preserved feature stays as it was through an edit next to it or of its box, a save, and a reopen. The saved copy opens with no repair prompt.
- Full rendering means that every test presentation of the feature matches its reference PDF within the fidelity thresholds. The feature has no approximation of its own. The line model, glyph advances, and missing glyphs apply to all text.
- Macros, OLE objects, audio, and video never run or play. The editor shows a poster or a labeled placeholder and keeps the object on save.

## Fonts

The editor measures and paints text with font bytes, so a line breaks at the same place on every machine that has the same fonts.

- Embedded fonts (`p:embeddedFontLst`) are decoded in memory for one document. The editor honors their embedding permissions, and never writes them to disk or caches them across documents.
- Without other fonts, the editor uses metric-compatible substitutes from `@docx-editor.dev/fonts`. A substitute has the same advance widths as the font it replaces, so lines break at the same places.
- You can supply your own font bytes. See [Fonts](/docs/customization/fonts).

The editor lists the families it substituted in `snapshot().substitutedFonts`, and `PptxEditor.FontNotice` shows them to the user.

## Known approximations

Each item below is a place where the renderer does not yet follow the specification exactly, or where the specification does not state the behavior.

- **Line model.** Line heights and baselines follow measured rules for Latin, Japanese, and Arabic text, from each font's own ascent and descent, and each baseline rounds to a whole point from the top of the text. Diagram text spaces its lines on the font's ascent plus descent, not on 1.2 times the font size. The rules are not measured for other scripts or for vertical text. A missing font keeps its line metrics for common Latin and East Asian families. For other families, a baseline can be off by up to a few points. Text that is taller than a centered or bottom-anchored body can be 1 to 3 pt off.
- **Long text clusters.** Grapheme clusters longer than 256 UTF-16 units paint in bounded pieces, including bullets and empty-list caret markers. Surrogate pairs stay together. Shaping does not cross piece boundaries. Source text, caret boundaries, and character positions remain unchanged.
- **Glyph advances.** The text shaper's advances can differ from other renderers by a small amount per glyph. A centered or right-aligned line can start up to 0.5 pt away, and a line near the edge of its box can break at another word. A font that the deck names kerns (`kern`) only when it has a `kern` table, as measured on reference PDFs. A substitute font, also one from a host substitution, keeps its own kerning pairs. Unit tests cover substitution rules. Substitution fidelity is not measured against reference PDFs.
- **Color transform spaces.** `a:tint`, `a:shade`, and `a:inv` use linear RGB, and the `a:lum*` transforms use HSL. The other transforms are not measured against a reference.
- **Gray transform.** `a:gray` uses Rec. 709 weights on sRGB components. One measured color confirms it, so other weights are not ruled out.
- **Blur.** The specification does not define the blur kernel. Shadows use a Gaussian blur with a standard deviation of a third of `blurRad`, as measured on reference PDFs. Reflections use half of `blurRad`, which is not measured. `a:blur` uses the shadow kernel and needs the drawing module of `@pptx-editor.dev/pro` (EigenPal Pro License).
- **Shadow skew.** `kx` and `ky` skew after the `sx` and `sy` scale, about the `algn` point.
- **Glow and soft edge.** These effects, the inner shadow, and the reflection need the drawing module of `@pptx-editor.dev/pro` (EigenPal Pro License). Without it, a shape paints without them, and save keeps them. The Shape Effects menu can still remove them. A glow grows the outline by half of `rad` and blurs it by the other half. A soft edge shrinks the outline by 0.84 of `rad` and blurs it by `rad`. Reference PDFs give both rules, measured for glows of 5 to 18 pt and soft edges of 2.5 and 10 pt. How fill transparency changes them is not measured: a glow takes the fill's alpha as its strength. A soft edge removes a part of the shape that is thinner than 1.7 times `rad`. The outline grows and shrinks by a set of rectangles, not a circle: a curved edge can be up to 8 % off, and a sharp corner up to 29 %. A glow larger than 200 pt draws as a 200 pt glow, and a soft edge shrinks the outline by at most 100 pt, so a huge radius never stops the page.
- **Preset shadows.** `a:prstShdw` draws as a hard copy of the shape at `dist` and `dir`. The perspective presets squash the copy to half its height on the bottom edge and lean it by 60°. The double and box presets add a second, lighter copy. Reference PDFs give these shapes for the 20 presets at one distance. Other distances and colors are not measured.
- **3-D shapes.** Bevels, contours, extrusions, and camera rotations need the drawing module of `@pptx-editor.dev/pro` (EigenPal Pro License). Without it, a 3-D shape draws flat, and save keeps its 3-D properties. A bevel draws as shaded strips along the outline. The light model is fitted to the circle and angle bevels under the three-point light from the top. Other bevel profiles, light rigs, light directions, and materials are approximate. The face of a shape keeps its fill color. A turned camera draws as a parallel projection, also for perspective presets. The extrusion shows only under a turned camera, and its sides are lit as if the light turns with the shape. The outer shadow is placed on the face and turns with it. The glow follows the turned face and lies under the extrusion; the glow and the shadow do not include the extrusion. A half turn mirrors the face and its text. A face turned edge-on draws only its extrusion. Bevels, contours, and extrusion sides follow at most 1,024 points of the outline. Bottom bevels and text in 3-D (`a:bodyPr/a:scene3d`, `a:sp3d`) are not drawn.
- **Effects not drawn.** `a:effectDag`, group effects, text effects, and some fill overlays are not drawn. They stay in the file.
- **Fill overlay.** `a:fillOverlay` blends with the shape's own fill only. Over a semi-transparent fill, the result is opaque where the overlay is.
- **Gradient colors.** A gradient with exactly two stops, at 0 and 100 %, bends each color channel toward the larger of its two end values. A gradient with three or more stops interpolates linearly in sRGB.
- **Path gradient focus.** A circle path gradient draws as a focal radial gradient. A focus that is outside the circle or on it moves the circle out slightly.
- **Gradient tiles.** A tile rectangle (`a:tileRect`) sets the circle of a circle path gradient and the outer edge of a rectangle path gradient. A tile rectangle that is smaller than the shape draws as one tile, not tiled.
- **Rectangle path gradients.** `path="rect"` draws as four trapezoids. The joins along the diagonals can show seam pixels.
- **Shape path gradients.** `path="shape"` draws as bands of the outline, scaled about the focus. Steps between bands can show.
- **Pattern tiles.** The preset patterns are 8 × 8 tiles of 1 pt pixels, on a grid from the top-left corner of the slide, square to the slide. The specification gives no bitmaps. All 54 bitmaps and the grid of rotated and flipped shapes are measured on reference PDFs. A shape in a scaled group keeps 8 pt tiles on the slide grid. The tiles of text start at the corner of the text, and the tiles of a table cell at the corner of the cell. These cases, line patterns, and slide backgrounds are not measured.
- **Path fill modes.** Preset paths with `fill="darken"`, `"darkenLess"`, `"lighten"`, and `"lightenLess"` scale the fill color toward black or white by fixed factors. The specification gives no factors.
- **Fill rotation.** Gradient and picture fills always turn with a rotated shape. `rotWithShape="0"` is ignored.
- **Gradient text.** A gradient on text spans the bounds of the whole text body.
- **Tiled pictures.** The tile size comes from the image's pixels and resolution, at 72 DPI when the image states none.
- **Picture shape fill.** A picture's own fill, behind the transparent areas of the image, is not drawn.
- **Picture brightness and contrast.** `a:lum` adds brightness to each component, then scales around mid-gray by contrast. The specification gives no formula, so washed-out pictures can draw lighter than expected.
- **Picture recolor.** Grayscale, duotone, and black and white take the luminance with Rec. 709 weights. The specification gives no weights.
- **Dashes on picture borders.** A picture's border draws outside the picture. Dashes get butt caps, and round dots draw as squares.
- **EMF and WMF pictures.** They draw as a PNG at 192 DPI, at most 4096 pixels on a side, so a large zoom can show pixels. Text in a picture draws with the fonts that the editor loaded for the deck. The converter replaces a font that is not loaded with a loaded font of the same pitch and family. With no loaded fonts, text draws with the fonts of the browser. The placeholder shows until the PNG is ready.
- **Inset lines.** `a:ln/@algn="in"` draws as a centered line. A picture's border always draws outside the picture.
- **Hyperlink text.** Link text draws in the theme `hlink` color with a single underline, unless the run states otherwise.
- **Dash complexity.** Shape and picture outlines and table borders draw solid when their geometry could require more than 100,000 dash segments. The engine estimates this count from curve control polygons. SVG and PDF use the same result. Save preserves the original dash pattern.
- **Compound lines.** The specification gives no band widths. The bands of `dbl`, `thickThin`, `thinThick`, and `tri` lines are measured on reference PDFs, on closed paths and on a straight open line. On an open path, the outer band is on the left of the path's direction. The dashes of a closed path start where its closing segment starts. On an open path, each band takes the line's cap, so a round cap draws one cap per band. Counterclockwise and self-crossing paths, curved open paths, caps, and dashed lines on curves are not measured. A path whose bands would take more than 16,384 points draws its bands with masks, and an open `thickThin` or `thinThick` line then draws as `dbl`.
- **Paths without a move.** A custom geometry path whose first drawing command is not `a:moveTo` draws nothing, also when a later `a:moveTo` follows. Each path of a shape follows this rule on its own.
- **Text in flipped shapes.** Glyphs are never mirrored. Under a net horizontal flip, text stays upright. Under a net vertical flip, it turns 180°.
- **Content placeholders.** `pic`, `tbl`, and `chart` placeholders inherit the master's body placeholder and its text style. `clipArt`, `dgm`, and `media` placeholders inherit no master placeholder.
- **Small caps.** Lowercase letters draw at 80 % of the size.
- **Underline styles.** Underline styles other than `sng` and `dbl` draw as a single line. `a:uLn` is ignored.
- **Missing glyphs.** A character counts as missing when the font's character map does not contain it, even when the shaper would draw a similar glyph in its place, such as a hyphen for a non-breaking hyphen. A missing character takes a fallback font that contains it. If no font contains it, layout estimates its width: 1 em for East Asian characters, the font's hyphen width for a hyphen or dash, and 0.5 em for others.
- **East Asian, complex-script, and symbol fonts.** Each character takes the `a:ea`, `a:cs`, `a:sym`, or `a:latin` font of its slot. Which characters that both Latin and East Asian text use take `a:ea` follows a fixed list and the run's `lang` and `altLang`. In a run whose `lang` is a complex-script language, digits, punctuation, and symbols take `a:cs`. A theme script font (`a:font`) applies only through `lang` or `altLang`. A character that the slot's face lacks uses the first loaded face that has it, East Asian faces first. Lines with Malgun Gothic and Arial text can be about 1 pt off their baseline. East Asian punctuation does not compress.
- **Right-to-left text.** Right-to-left paragraphs (`a:pPr/@rtl`) lay out with the Unicode Bidirectional Algorithm (UAX #9). Margins, indent, and the bullet start at the right edge, and a number such as `1.` reads `.1`. `algn="l"` and `algn="r"` name the left and right edges in both directions. A justified last line starts at the right. A run whose letters all read against the paragraph keeps its punctuation at its edges. Quotation marks split across two runs do not pair. The PDF export draws Arabic letters in their isolated forms, without joining, in cells measured from the joined text, so letters can overlap; the editor's paint joins them. At a few direction boundaries, one caret position shows at two places, and a peer's caret shows at the default side.
- **Tab stops.** Right, center, and decimal tab stops in right-to-left text, or in text that does not wrap, are not measured.
- **Anchoring and alignment variants.** `anchorCtr` is ignored. `anchor="just"` and `anchor="dist"` behave as top. `justLow` justifies as `just`, and `thaiDist` distributes as `dist`. Neither is measured.
- **Upright East Asian text (`eaVert`).** East Asian characters draw upright, centered across the line, with the em box (0.12 em below the baseline) centered in the advance. Vertical metrics and vertical glyph alternates are not used. Turned Latin text in an `eaVert` line can sit 1 pt off its baseline.
- **Stacked text (`wordArtVert`, `wordArtVertRtl`).** Each letter advances by 1.425 times the font size, as measured on Carlito, and is centered in a square cell of that advance. `wordArtVert` lines start at the left edge and go to the right; `wordArtVertRtl` lines start at the right edge and go to the left. Letters can be up to 1.5 pt off across the line.
- **Other vertical text types.** `mongolianVert` lays out as `vert`, with its lines from the left edge to the right; Mongolian script is not drawn in its vertical forms. The editor does not set this type.
- **Superscript and subscript.** Raised and lowered text is two thirds of the run size.
- **Bullets on aligned lines.** On a centered or right-aligned line, the bullet moves with the text.
- **Numbering schemes.** Every `a:buAutoNum` scheme draws its own counter and punctuation. Reference PDFs measure Latin letters, Arabic and Roman numbers, Hebrew letters (items 1 to 4), and Arabic letters (items 1 and 2). Thai, Hindi, East Asian, double-byte, circled, and Arabic abjad numbers, and Hebrew and Arabic letters above the measured items, follow the standard's description of their counter, with no measurement. Past the last letter, Latin, Thai, and Hindi numbers continue as letter pairs, and Hebrew and Arabic numbers repeat a letter. An unknown scheme draws as `1.`.
- **Symbol font bullets.** A Wingdings, Webdings, or Symbol bullet draws with that font. When the font is not available, the editor draws a Unicode character that looks the same.
- **Trailing line break.** A line break at the end of a paragraph adds an empty line, sized by the paragraph mark.
- **Default table style.** A table that names Medium Style 2 - Accent 1 without its definition in the file uses a built-in definition.
- **Rotated cell text.** Vertical text in a table cell wraps at the row height and does not grow the row.
- **Table cell effects.** `a:cell3D` and table effects are not drawn.
- **Coincident cell borders.** Where two cells state different borders for one edge, the later cell in row order draws on top.
- **Inconsistent cell merges.** ECMA-376 does not define a table whose merge markup disagrees with itself. A cell with `hMerge` or `vMerge` that no `gridSpan` or `rowSpan` reaches draws as a normal cell, with its own text and spans. A span past the grid ends at the grid, and a span into an earlier merged cell ends before that cell. These rules are not measured.
- **Text warp.** Warped text (`a:prstTxWarp`) lays out flat, and then each glyph outline maps into the warp's paths. A warp with two paths, or with pairs of paths, stretches the ink bounds of its lines between each pair. With more than one pair, the ink bounds of each pair grow about their center to the widest and tallest bounds of all pairs, so every pair keeps one text size. A warp with one or three paths lays each line along a path at its own size: the baseline is 0.164 em below the path, and the other lines stack at their face height. These rules are measured on Liberation Sans. Lines split between pairs in order, which is not measured for every warp. On `textStop`, the reference text along the top path is about 2 % narrower than along the bottom path. The engine uses the same width on both paths. Vertical and rotated text, diagram text, and text with more than 2,000 characters draw flat. The caret and the selection use the flat layout. Each character draws its nominal glyph without shaping, so ligatures and complex-script forms are lost. A picture bullet turns and stretches with the warp but does not bend. Synthetic bold and italic are not drawn on warped text.
- **Diagram drawings.** A diagram draws the shapes of its saved drawing (`dsp:drawing`) at their saved positions, sizes, and line widths. The diagram does not lay out again from its data model, layout, and style parts, so it does not change when its frame size or data changes. A diagram with no saved drawing shows a placeholder. A drawing with more than 512 shapes or 8 group levels also shows a placeholder, and so do the diagrams of a slide past 4096 shapes and groups together.
- **Equations.** An equation (Office Math, `a14:m`) lays out with the rules of TeX: atom classes and the spaces between them, script sizes of 73 % and 60 % rounded down to half a point, and shifts measured on STIX Two Math at 18 pt. Normal text (`m:nor`) keeps its own size in a script, also in a nested script and a radical degree. A line grows only where an equation passes it: each glyph claims its ink, a glyph with no outline claims the box of the face that draws it, and rules and signs claim their outlines. The rule of a radical also claims 0.078 em above it, the radical extra ascender of STIX Two Math. The next line starts where the ink ends. At single spacing, a text line below a display fraction that is alone on its line is 9 pt lower than in the reference: the fraction draws 8 pt taller, because the reference places its numerator closer to the rule. Other text lines above and below an equation come within 1 pt of the reference PDFs of the `equations` and `equation-lines` fixtures and slide 1 of `preserved-content`. Above single spacing, the equation keeps its extent and the spacing adds its share of a text line. The reference adds more: at 150 %, it makes a line of a display fraction 17 pt taller, and this layout 10 pt. Stacked display fractions then stand 3 pt farther apart than in the reference, because each one is taller, and the first one is 8 pt higher. Fraction rules, radical signs, stretched delimiters, and braces draw as filled outlines, not as glyphs of the math font. Large operators draw their glyph at a larger size, not the font's display variant, and accents draw their spacing form over the base. Where a run's font is missing, the equation draws in STIX Two Math or Latin Modern Math when the host has them, else in Liberation Serif with italic letters. Baselines and line heights differ from the reference by up to a few points. An equation with a construct that the layout does not read, or with more than 4,000 elements or 32 levels, draws the fallback of its text box.

## Approximations after editing

An edit lays out the slide again through the same pipeline, and applies the autofit rules of the text body (`a:normAutofit`, `a:spAutoFit`; ECMA-376 Part 1, 21.1.2.1). These recomputations are approximations:

- **Shape autofit.** Rotated text, text in more than one column, and text in a shape that is not a rectangle get an estimated size.
- **Shrink on overflow.** Each edit fits the text again from 100 %. A title takes one step at most, a 90 % font scale, and longer text then overflows. Other text first reduces line spacing by 10 %, then lowers the font scale in steps with 10 % and then 20 % less line spacing, and the editor writes the first step at which the text fits. Below an 85 % font scale, each step has 20 % less line spacing only. Empty paragraphs at the end of the text do not count. Steps below a 55 % font scale are estimated.
- **Resize several shapes.** Rotated shapes scale in the slide's axes.
- **Ungroup a group with a non-uniform scale.** Each child keeps its center, size, and rotation.
- **Change case.** A letter whose other case has a different length, such as `ß`, stays as it is. The language of the run is not used.
- **Crop, Fill, Fit, Change Picture, Format Picture, and Reset Picture.** In a group with a non-uniform scale, a crop is estimated. Fill and Fit center the crop on the image. Change Picture fits the new image in the old frame and removes the crop.
- **Picture and shape presets.** The Recolor, Corrections, Transparency, picture style, Shape Effects, and Shape Styles galleries write fixed preset definitions.
- **Distribute.** A turned object counts with its unrotated box.
- **Flip and rotate in a group with a non-uniform scale.** The result is estimated.
- **Objects in `mc:AlternateContent`.** The editor edits the copy it draws: the first `mc:Choice` it can draw, else the `mc:Fallback`. Hide, rename, and the aspect lock also change the other copies. A delete removes every copy. When the editor draws a `mc:Choice`, another edit removes the copies in the other branches, and a duplicate goes into the same `mc:Choice`. A reader that selects another branch then shows nothing for the object, not its old state. In a collaboration room, an undo brings back the copies that its step removed, also when a peer edited the object after that step. When the editor draws the `mc:Fallback`, other edits do not change the `mc:Choice` copies.
- **Table frame size.** After a table edit, the frame takes the laid-out table size. Row heights stay minimums.
- **Insert table.** A new table goes in the center of the slide, not into an empty content placeholder.
- **Split cells.** New columns and rows share the width or height of the cell they split.

## Approximations of the PDF export

[`@pptx-editor.dev/pptx-to-pdf`](https://www.npmjs.com/package/@pptx-editor.dev/pptx-to-pdf) paints the same layout as the editor, so the approximations above apply to it too. It adds these. Each one reports a diagnostic code on the export result, and the package README lists every code.

- **Shadow and glow blur.** Drawn as layers of growing outlines, not as a Gaussian blur.
- **Opaque silhouettes.** Fill transparency does not lighten a shadow, and a picture's shadow takes the shape of its frame.
- **Inner shadows.** The outer half of an outline is not shaded, and an unfilled shape gets no inner shadow.
- **Soft edges.** Drawn hard.
- **Blur.** `a:blur` is not drawn.
- **Reflection blur.** A reflection is drawn with its fade, without its blur.
- **Gradient lines.** Drawn in one color.
- **Gradient stops.** At most 64 stops are drawn.
- **Fills outside the box.** A rectangle path gradient or a picture fill paints the shape's box only.
- **Tiled pictures.** Drawn stretched over the box.
- **Picture color effects.** Grayscale, duotone, brightness and contrast, and black and white are not applied.
- **Compound lines.** Dashed compound lines, compound table borders, and compound lines whose bands would take more than 16,384 points draw as one line.
- **SVG pictures.** The PNG fallback of the picture is drawn.
- **Text.** Synthetic bold and italic are not drawn, upright vertical characters draw rotated, and a character that the font does not have is not drawn. Dotted, dashed, wavy, heavy, and word-only underlines draw as one single line, as in the editor.
- **Not drawn.** Patterns on text and lines, picture fills on text, text outlines, other picture formats, diagrams with no saved drawing, OLE objects with no picture, other graphic frames, and table frames with no grid. Charts draw through the Pro drawing module, which the export always installs. Chart types outside that module show a placeholder (see [Charts](/docs/guides/charts)).
