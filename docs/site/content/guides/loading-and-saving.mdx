Use `load()` to open PPTX bytes and `save()` to get the edited file. Your application owns storage and downloads.

The examples accept an existing `Editor`. Get it from your adapter or [create a core editor](/docs/core).

## Open a file

Read a browser `File` as bytes. Check the result before you report success:

```ts
import type { Editor } from '@pptx-editor.dev/core/contracts';

export async function openFile(editor: Editor, file: File) {
  const bytes = new Uint8Array(await file.arrayBuffer());
  const result = await editor.load(bytes);
  if (!result.ok) throw new Error(result.reason);
}
```

Before replacing a presentation, ask the user to save or discard unsaved changes. `load()` replaces the document and its history.

## Open from a URL

Check the HTTP response before passing its body to the editor:

```ts
import type { Editor } from '@pptx-editor.dev/core/contracts';

export async function openUrl(editor: Editor, url: string) {
  const response = await fetch(url);
  if (!response.ok) {
    throw new Error(`Download failed: ${response.status}`);
  }
  const bytes = new Uint8Array(await response.arrayBuffer());
  const result = await editor.load(bytes, { startSlide: 0 });
  if (!result.ok) throw new Error(result.reason);
}
```

`startSlide` uses a zero-based index. For a long presentation, `load()` resolves when the first requested slide is ready. See [Long decks](/docs/guides/long-decks).

## Replace the document as one undoable edit

`load()` resets selection and undo history. To keep undo history, run the `replaceDocument` command. It replaces the whole presentation with a PPTX file as one undo step, and a collaboration session shares it as an ordinary edit. Use it to restore a version, render a template again, or apply the output of a server tool. This example expects your own `renderTemplate` function:

```ts
import type { Editor } from '@pptx-editor.dev/core/contracts';

declare function renderTemplate(pptx: Uint8Array): Promise<Uint8Array>;

export async function rerender(editor: Editor) {
  const saved = editor.save();
  if (!saved) throw new Error('The presentation cannot be saved.');
  // Take the handle together with the presentation.
  const expected = editor.getDocumentHandle();
  const pptx = await renderTemplate(saved);

  const result = editor.exec({ type: 'replaceDocument', pptx, expected });
  if (!result.ok) {
    // The presentation and its undo history are unchanged.
    console.warn(result.replaceDocument?.code, result.reason);
  }
}
```

The replacement behaves as follows:

- One undo returns to the presentation before the replacement. Earlier undo steps stay available.
- Parts that the editor does not interpret arrive as the file has them.
- The selection stays when its shapes and text survive. Otherwise it clears. The current slide index and the zoom stay.
- Slides whose parts did not change keep their painted thumbnails and canvas content.
- A file identical to the open presentation succeeds with `changed: false` and adds no undo step.
- With `expected`, the command refuses with `staleDocument` unless the open presentation is still the one the handle describes. `reason: 'edited'` means anyone edited it, another participant included. `reason: 'otherDocument'` means another presentation was loaded, because each `load()` gives the handle a new `loadId`.

`result.replaceDocument` carries the typed outcome. A refusal has a stable `code`, an English `message`, and for some codes a `reason`. Branch on this `code`. The top-level `result.reason` is the generic i18n key `errors.unsupported`, and `result.detail` repeats the `code`:

| `code` | Situation | Action |
| --- | --- | --- |
| `staleDocument` | `reason` is `edited` or `otherDocument`: the open presentation is not the one `expected` describes. | Read the presentation again and redo your work. |
| `invalidRequest` | The arguments are wrong. | Fix the call. A replacement is always its own undo step. |
| `invalidDocument` | The bytes are not a valid PPTX file. | Report the failure. |
| `unavailable` | No presentation is open, the presentation is still opening, or the editor was destroyed. | Retry when a presentation is open. |
| `busy` | A document refresh is replacing the presentation. | Wait for it to finish, then retry. |
| `editNotPermitted` | `reason` is `viewing`. A retry does not help. | Change the editing mode, or call `load()` outside a collaboration session. |
| `editUnsupported` | `reason` is `differentMainPart`, `unsupportedDifference`, or `collaborationRefused`. | Outside a collaboration session, call `load()` instead. |

The `reason` type also lists `suggesting`, `protected`, and `collaborationUnavailable` for DOCX Editor compatibility. PresentationML has no suggesting mode or enforced protection, and a PPTX Editor collaboration session accepts edits while it is attached, so PPTX Editor does not produce them. `collaborationRefused` means that a collaboration session is attached and the editor refused the edit.

Use `replaceDocument` when your code owns the timing. Use the [Document refresh API](/docs/guides/document-refresh) for server jobs that return results while the user keeps editing. Refresh adds capture, sequencing, change highlights, and recovery, and its `mode: 'edit'` runs this command.

## Download the edited file

`save()` is synchronous. It returns `Uint8Array` bytes, or `null` when saving is unavailable:

```ts
import type { Editor } from '@pptx-editor.dev/core/contracts';

export function downloadPresentation(editor: Editor) {
  const bytes = editor.save();
  if (!bytes) throw new Error('The presentation cannot be saved.');

  const blob = new Blob([bytes], {
    type: 'application/vnd.openxmlformats-officedocument.' + 'presentationml.presentation',
  });
  const url = URL.createObjectURL(blob);
  const link = document.createElement('a');
  link.href = url;
  link.download = 'presentation.pptx';
  document.body.append(link);
  link.click();
  link.remove();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
}
```

Saving finishes any pending slide parsing. It can discover damage and return `null`. Show a failure message instead of downloading an empty file.

## Unused picture data

Saving omits unused image relationships from parsed slides, layouts, masters, and notes. It removes image parts without remaining relationships. Shared images and images referenced by unknown relationship types or opaque parts stay in the file. Unreadable relationships or unknown relationship metadata disable this cleanup. Bounded reference scans retain image relationships when their work limit is reached.

Cleanup changes only the saved file. The live document and collaboration room retain image data for undo and pending peer edits.

## Save to your server

Send the bytes to your own authenticated endpoint. This example expects an application route at `/api/presentations/current`:

```ts
import type { Editor } from '@pptx-editor.dev/core/contracts';

export async function uploadPresentation(editor: Editor) {
  const bytes = editor.save();
  if (!bytes) throw new Error('The presentation cannot be saved.');
  const response = await fetch('/api/presentations/current', {
    method: 'PUT',
    headers: { 'Content-Type': 'application/octet-stream' },
    body: bytes,
  });
  if (!response.ok) throw new Error(`Save failed: ${response.status}`);
}
```

Clear your unsaved indicator only after storage succeeds. Serialize uploads or use version checks to prevent older saves from replacing newer saves.

## Follow document changes

Use `onEditorEvent` instead of saving after every state notification:

```ts
import { onEditorEvent } from '@pptx-editor.dev/core/editor';
import type { Editor } from '@pptx-editor.dev/core/contracts';

export function watchChanges(editor: Editor, notify: () => void) {
  return onEditorEvent(editor, 'change', notify);
}
```

Call the returned function when your integration unmounts. The `change` event includes completed or failed loads and read-only transitions. It excludes zoom and selection changes.

If you autosave, debounce edits and handle `save()` returning `null`. A revision counter tracks changes, not whether undo restored the saved file.
